TIMPANI · Event-Driven Workload Support

Radar–FCW 이벤트 흐름
P1: 한 Event–한 Job · 도달 기준 마감 감지

2026-11-11 합의한 수정 방향 / 구현 전

레이더 경보를 인지한 시각부터 FCW(Forward Collision Warning — 전방 충돌 경고) 판단이 끝날 때까지를 추적합니다. 앱은 이벤트와 작업의 연결을 명시하고, TIMPANI는 CPU 예산과 실행 상태를 관리하며 마감 경과를 감지합니다.

문서 상태: 기존 설계의 활성화 기준 근사와 배치 소비를 변경하는 P1(Phase 1 — 1차 구현) 목표입니다. 정본 설계 전체에 반영되거나 구현된 기능이 아닙니다. 아래 전달·감시 블록은 필요한 책임을 나타내며, 특정 공개 API나 타이머 구현을 확정하지 않습니다.

1. 이번 수정의 세 가지 원칙

한 Event–한 Job수락한 경보마다 독립된 작업을 만듭니다. 처리 중 도착한 다음 경보는 다음 작업으로 남깁니다.
마감은 도달 시각 + D워커가 늦게 깨어나거나 예산 보충을 기다려도 마감이 뒤로 이동하지 않습니다.
끝나기를 기다리지 않고 감지작업이 대기·실행·실행 보류 중이어도 마감이 지나면 허용 감지 지연 안에 실패를 기록합니다.

Event(이벤트)는 수신 경보 한 건, Job(작업)은 그 경보를 처리하는 한 단위입니다. 이벤트 데이터·식별자·도달 시각·작업 연결은 통지와 재시작 과정에서도 어긋나지 않아야 합니다.

2. 전송과 처리의 역할을 분리한다

t0는 이 예제의 수신 콜백에서 유효한 경보로 식별한 시각입니다. 그 이전의 전송·수신 스레드 대기는 이 응답시간에 포함되지 않습니다. IRQ(Interrupt Request — 인터럽트 요청) 처리나 미들웨어 내부 스레드가 FCW 워커의 예산에 자동 포함되는 것은 아닙니다.

3. 정상 처리: 마감은 하나, t0 + D

용어의미측정·계약
R — Response time
응답시간		t2 − t0. CPU 대기·선점·예산 보충 대기를 포함해당 Event의 고정된 도달 시각과 Job 완료를 연결
D — Relative deadline
상대 마감시간		도달 후 완료까지 허용되는 시간t2 ≤ t0 + D이면 충족. 활성화·수락 지연만큼 연장하지 않음
C — CPU 실행시간 예산선언의 runtime에 대응. R과 다름실제 CPU 실행 구간을 합산·차감. 예산 소진 시 실행 보류
MIT — Minimum Inter-arrival Time
최소 도달 간격		같은 발생원의 연속 Event 간격 하한Event별 도달 시각 차이로 검사. 위반해도 마감 기준을 재설정하지 않음

4. 마감 실패: 완료되지 않아도 감지한다

경합 처리: 마감과 같은 시각까지 완료된 Job은 성공입니다. 완료 기록 수집이 늦었다는 이유만으로 실패로 판정하지 않습니다. 완료와 타이머가 경합해도 실제 완료 시각으로 판정하고 중복 계수를 막아야 합니다. 마감 실패는 자동 취소를 뜻하지 않으며 계속 실행·취소 정책은 별도입니다.

5. 처리 중 다음 경보가 와도 작업을 합치지 않는다

순서상황유지할 연결
1경보 A 수락 → Job A 처리 시작A 식별자·A 도달 시각·A 마감 고정
2A 처리 중 경보 B 도달·수락B를 별도 대기 항목으로 보존하고 B의 기한도 감시. A 시각을 덮어쓰지 않음
3A 완료 → 수면 없이 B 처리 시작A 완료와 Job B 시작을 명시. 새로운 커널 깨움이 없어도 서로 다른 Job
4B 완료 또는 B 마감 경과B 도달 기준으로 독립 판정. Job 시작·예산 보충으로 B의 마감을 늦추지 않음

새 Job ≠ 새 CPU 예산. CBS(Constant Bandwidth Server — CPU 사용량을 예산과 보충 규칙으로 제한하는 서버)의 잔여 예산과 보충 규칙은 별도로 적용합니다. Job 도중의 블로킹은 첫 구현에서 피하고, 로그 등 잠들 수 있는 작업은 다른 스레드로 넘깁니다.

6. 구현 전에 정할 사항과 검증 경계

  • 수락·게시: 데이터와 이벤트 정보가 함께 사용 가능해지는 경계를 정의합니다. 통지 거절·대기열 넘침은 완료가 아닌 거절·폐기로 기록합니다.
  • 복구: 재시작 시 데이터와 시각이 어긋나지 않도록 동기화하고, 이전 등록의 타이머·완료·종료 정보가 새 등록을 변경하지 않도록 세대를 구분합니다.
  • 기한 감시: 미완료 감지 지연 상한, 통지 전 수락 지연의 처리, 타이머와 완료의 경합 규약을 확정합니다. 감지 지연 0을 가정하지 않습니다.
  • 예산·승인: 틱 단위 초과 실행과 스케줄링 비용을 다른 앱의 간섭 계산에 반영하고, 필수 통계를 상세 추적의 활성 여부와 분리합니다.
  • 지원 수준: 등록 워커의 실행만 관측하는 경로를 Event별 도달 기준 마감 지원과 동일하게 설명하지 않습니다.
  • 두 앱 검증: SOME/IP FCW와 비-SOME/IP 센서 앱을 같은 계약으로 연결하고, 정상·버스트·과실행·동시 실행·재시작을 검증합니다.

FCW 기존 C=2ms, D=5ms, MIT=18ms는 검증 완료 값이 아닙니다. 타깃의 실제 처리시간·전달 지터·다른 태스크의 간섭으로 확정합니다. t0 이전 유실·지연과 실제 결과 전달까지의 전체 경로 보장은 별도 설계 대상입니다.
